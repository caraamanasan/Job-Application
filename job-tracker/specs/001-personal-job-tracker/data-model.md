# Data Model: Personal Job Application Tracker

## Application

Represents one job opportunity tracked by the local user. Multiple applications may share the same company and role.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | Integer | Yes | Primary key, generated by SQLite |
| `company` | Text | Yes | Trim surrounding whitespace; reject empty values and values over 200 characters |
| `role` | Text | Yes | Trim surrounding whitespace; reject empty values and values over 200 characters |
| `job_url` | Text | No | Blank becomes null; if supplied, must be an absolute HTTP or HTTPS URL of at most 2048 characters |
| `date_applied` | Date | Yes | ISO `YYYY-MM-DD`; valid calendar date and not in the future |
| `status` | Text enum | Yes | One of `Applied`, `Assessment`, `Interview`, `Offer`, `Rejected`; defaults to `Applied` |
| `notes` | Text | No | Blank becomes null; at most 5000 characters |
| `created_at` | Timestamp | Yes | UTC timestamp assigned on creation |
| `updated_at` | Timestamp | Yes | UTC timestamp updated when the record changes |

## Persistence Rules

- Keep the SQLite database in the Flask instance directory, outside static and frontend build directories.
- Enforce `NOT NULL` and allowed-status constraints in SQLite as well as validating in Python.
- Do not add a user table or `user_id` in the single-user local version.
- Do not make company plus role unique; repeat applications are valid.
- Use parameterized SQL for all reads and writes.
- Filter and search in the query layer. Search company or role case-insensitively; combine an active search term and status filter with AND semantics. Send search terms in a JSON body, not a URL query string, to keep them out of access logs.
- Deleting an application removes only the selected row after the UI's explicit confirmation.

## Validation Boundary

The React UI provides immediate feedback, but Flask validates every create, update, and status change before writing. Invalid requests return field-specific errors and do not partially update the row. SQLite constraints remain a final integrity safeguard.
